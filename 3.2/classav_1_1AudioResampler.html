Detailed Description

The typical use is a decode-transform-encode pipeline: the decoder produces whatever the stream contains, the encoder accepts one specific layout, and this is the component in between. Construct it with both layouts, or call init() later; push() feeds samples in and pop() takes them out.

A single push can produce several output buffers, and the resampler holds an internal delay, so popping until it returns nothing is part of the contract.

Examples
api2-decode-encode-audio.cpp, and api2-decode-rasample-audio.cpp.
