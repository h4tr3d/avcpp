Ремиксинг

Ремиксинг переносит сжатые пакеты из одного контейнера в другой, не декодируя их. Это самый дешевый способ сменить контейнер, убрать поток или нарезать по ключевым кадрам, и лучшая первая проверка конвейера: если ремиксинг дал проигрываемый файл, значит контейнерная часть корректна.

Копирование описаний потоков

// Copy streams
for (size_t i = 0, ostIdx = 0; i < ictx.streamsCount(); ++i) {
auto ist = ictx.stream(i);
auto icodecpar = ist.codecParameters();
auto ocodec = icodecpar.decodingCodec();
// Source codec can be unsupprted by the target format. Transcoding required or simple skip.
if (!octx.outputFormat().codecSupported(ocodec)) {
clog << "Input stream " << i << " codec '" << ocodec.name() <<
"' does not supported by the output format '" << oformat.name() << "'\n";
continue;
}
auto ost = octx.addStream(ec);
ost.setCodecParameters(icodecpar);
ost.codecParameters().codecTag(0);
// We can omit codec checking above and got error FormatCodecUnsupported (error code or exception)
if (ec) {
if (ec == Errors::FormatCodecUnsupported) {
continue;
} else {
cerr << ec.category().name() << ": " << ec.message() << endl;
return 1;
}
}
ost.setTimeBase(ist.timeBase());
// setup mapping
streamMapping[i] = ostIdx++;
}

Ключевой вызов — stream.codecParameters(): он возвращает переносимое описание кодека внутри потока. Копирование его в выходной поток сообщает муксеру, что будет внутри пакетов, без открытия какого-либо кодека.

codecParameters().decodingCodec() ищет кодек по идентификатору, чтобы программа могла проверить, поддерживает ли целевой контейнер этот кодек. Муксер спокойно примет поток, который не умеет хранить, и ошибка проявится при записи, а не при настройке.

codecParameters().codecTag(0) очищает тег кодека. Теги — четырехсимвольные коды, специфичные для контейнера; оставленный входной тег заставит выходной поток заявлять тег из другого контейнера.

Перенос пакетов

while (true) {
auto pkt = ictx.readPacket();
if (!pkt)
break;
auto it = streamMapping.find(pkt.streamIndex());
string skip;
if (it == streamMapping.end()) {
skip = " [skip]";
}
clog << "pkt[" << pkt.streamIndex() << "]: tm=" << pkt.pts() << " / " << pkt.pts().seconds() << skip << '\n';
if (it == streamMapping.end())
continue;
pkt.setStreamIndex(it->second);
octx.writePacket(pkt);
if (duration) {
if (pkt.pts() > duration)
break;
}
}

Пакеты переписываются, а не пересчитываются: цикл только отображает индекс входного потока на выходной. Метки времени остаются в базе времени входного потока, поэтому в примере при настройке копируется setTimeBase() из входного потока.

writePacket() без аргументов осушает внутреннюю очередь муксера до writeTrailer(). Некоторые муксеры держат последние пакеты до трейлера; без слива они могут переупорядочиться или потеряться.

Что ремиксить нельзя

  • Кодек, который целевой контейнер не поддерживает. Пример пропускает такие потоки, и это законная политика: вместо аварийного завершения сообщается Errors::FormatCodecUnsupported.
  • Смену разрешения или параметров кодека посреди потока. Пакеты после смены относятся к другой конфигурации и требуют нового потока.
  • Все, что требует вмешательства в полезную нагрузку: фильтрация, масштабирование, пересчет времени.

Для этого нужно декодировать и кодировать: Декодирование и Кодирование.
