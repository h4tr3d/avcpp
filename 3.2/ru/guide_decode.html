Декодирование

Декодирование превращает сжатые пакеты в кадры. На входе — av::Packet, на выходе — av::VideoFrame или av::AudioSamples, а между ними стоит контекст декодера.

Форма цикла

У декодера есть входная очередь и выходная, и они не синхронны: один пакет может дать несколько кадров, а кадр может появиться спустя много времени после приема пакета. Контракт такой:

  1. send(packet) возвращает true, когда пакет принят, и false, когда декодер хочет, чтобы сначала осушили выход.
  2. receive() возвращает кадр или пустое значение, когда читать сейчас нечего.
  3. В конце потока flush() переводит декодер в режим слива, а receive() продолжает отдавать кадры, пока не вернет пустое значение уже окончательно. После этого isEof() становится true.

Эталон — example/api2-samples/api2-send-receive.cpp:

auto drain = [&]() -> bool {
for (;;) {
auto frame = dec.receive(ec);
if (ec) {
std::cerr << "Can't receive a frame: " << ec.message() << '\n';
return false;
}
if (!frame)
return true;
++frames;
}
};
av::Packet pkt;
while ((pkt = ictx.readPacket(ec))) {
if (pkt.streamIndex() != vst.index())
continue;
++packets;
for (;;) {
bool accepted = dec.send(pkt, ec);
if (ec) {
std::cerr << "Can't send a packet: " << ec.message() << '\n';
return 1;
}
// Drain what is available. A rejected send() means EAGAIN: the
// packet must be retried after the output queue is empty.
if (!drain())
return 1;
if (accepted)
break;
}
}
if (ec) {
std::cerr << "Read error: " << ec.message() << '\n';
return 1;
}

Обратите внимание, чего цикл не предполагает: он не считает, что один пакет — это один кадр, и не считает пустой receive() ошибкой. Пустой результат означает «сейчас ничего нет», а не «конец потока».

Настройка

av::FormatContext ictx;
ictx.openInput(argv[1], ec);
if (ec) {
std::cerr << "Can't open input: " << ec.message() << '\n';
return 1;
}
ictx.findStreamInfo(ec);
if (ec) {
std::cerr << "Can't find streams: " << ec.message() << '\n';
return 1;
}
av::Stream vst;
for (auto &&st : ictx.streams()) {
if (st.mediaType() == AVMEDIA_TYPE_VIDEO) {
vst = st;
break;
}
}
if (!vst.isValid()) {
std::cerr << "Video stream not found\n";
return 1;
}
av::VideoDecoderContext dec{vst};
dec.open(ec);
if (ec) {
std::cerr << "Can't open codec: " << ec.message() << '\n';
return 1;
}

VideoDecoderContext создается либо из потока — тогда кодек берется из параметров потока, — либо из Codec, когда кодек надо выбрать явно (так делает аппаратное декодирование, см. Аппаратное кодирование и декодирование).

Две настройки стоит знать до open():

  • setRefCountedFrames(true) заставляет декодер отдавать кадры со счетчиком ссылок. Такой кадр дешево копируется и остается валидным после следующего вызова receive(). Без этого буфер кадра принадлежит декодеру и переиспользуется.
  • open() принимает словарь опций: dec.open({{"threads", "4"}}, av::Codec(), ec) задает число потоков декодера, как это делает example/api2-samples/api2-decode.cpp.

Слив

// Switch the decoder to draining mode. flush() is idempotent and reports
// false only when the output queue must be drained before it is retried.
if (!dec.flush(ec)) {
if (ec) {
std::cerr << "Can't flush the decoder: " << ec.message() << '\n';
return 1;
}
if (!drain())
return 1;
if (!dec.flush(ec)) {
std::cerr << "Can't flush the decoder after draining\n";
return 1;
}
}
if (!drain())
return 1;

flush() возвращает false, когда выходную очередь надо осушить, прежде чем переключение в режим слива завершится; правильная реакция — вызвать лямбду drain() из примера и повторить flush(), он идемпотентен. Если слив пропустить, последние кадры каждого файла теряются молча, и это легко не заметить: кадров обычно немного.

Временные метки

Кадр несет метку показа (pts()) и базу времени (timeBase()). Метка задана в единицах базы времени, поэтому секунды — это pts().seconds(), а pts() — это av::Timestamp, который можно сравнивать, преобразовывать и печатать напрямую.

Не смешивайте метки из разных контекстов: у декодера, кодировщика и каждого потока своя база времени. Передавая кадр в другой компонент, задайте базу времени явно: frame.setTimeBase().

Устаревший путь

Старый код использует decode(packet), который возвращает не больше одного кадра за вызов, а остальное оставляет в декодере:

while (Packet pkt = ictx.readPacket(ec)) {
if (ec) {
clog << "Packet reading error: " << ec << ", " << ec.message() << endl;
return 1;
}
if (pkt.streamIndex() != videoStream) {
continue;
}
auto ts = pkt.ts();
clog << "Read packet: " << ts << " / " << ts.seconds() << " / " << pkt.timeBase() << " / st: " << pkt.streamIndex() << endl;
#if AVCPP_HAS_PKT_SIDE_DATA
for (auto side : pkt.sideData()) {
clog << " found packet side data: " << side.name() << endl;
if (side.type() == AV_PKT_DATA_MATROSKA_BLOCKADDITIONAL) {
assert(side.span().size() >= sizeof(uint64_t));
// BE
uint64_t idType{};
memcpy(&idType, side.span().data(), sizeof(idType));
//idType = std::endian::native == std::endian::little ? std::byteswap(idType) : idType;
idType = av_be2ne64(idType);
auto payload = side.span().subspan(sizeof(uint64_t));
clog << " matroska block additions id type = " << idType << endl;
if (!payload.empty() && idType == 100 /* vendor specific */) {
clog << " block additions data: " << std::string_view{(const char*)payload.data(), payload.size()} << endl;
}
}
}
#endif
VideoFrame frame = vdec.decode(pkt, ec);
count++;
//if (count > 100)
// break;
if (ec) {
cerr << "Error: " << ec << ", " << ec.message() << endl;
return 1;
} else if (!frame) {
cerr << "Empty frame\n";
//continue;
}
ts = frame.pts();
clog << " Frame: " << frame.width() << "x" << frame.height() << ", size=" << frame.size() << ", ts=" << ts << ", tm: " << ts.seconds() << ", tb: " << frame.timeBase() << ", ref=" << frame.isReferenced() << ":" << frame.refCount() << endl;
}

Для программных декодеров это до сих пор работает, и именно это показывает example/api2-samples/api2-decode.cpp. Не используйте этот путь с асинхронными аппаратными декодерами: там кадр может появиться гораздо позже, и он потеряется. Везде используйте send()/receive().

Аудио

Аудио декодируется так же, только с av::AudioDecoderContext и av::AudioSamples. Сэмплы бывают planar и packed в зависимости от формата; sampleFormat(), channelsCount(), sampleRate() и isPlanar() описывают раскладку, а av::AudioResampler конвертирует между раскладками, когда потребителю нужно другое.
