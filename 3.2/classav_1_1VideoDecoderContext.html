Detailed Description

Uses the send/receive API; see the class comment of CodecContext2 for the contract. The legacy decode() overloads remain available for software decoders and are convenient for one-shot conversions.

Examples
api2-decode-encode-video.cpp, api2-decode-filter-encode.cpp, api2-decode-overlay-encode.cpp, api2-decode-raw-h264.cpp, api2-decode.cpp, api2-hw-decode.cpp, api2-hw-scale.cpp, api2-hw-transcode.cpp, api2-scale-video.cpp, and api2-send-receive.cpp.

◆ hwFramesContext()

hw::FramesContext av::VideoDecoderContext::hwFramesContext ( ) const
noexcept

Returns the frames context owned by the decoder, if any. It exists when the codec needs one (avcpp derives it for codecs that advertise only AV_CODEC_HW_CONFIG_METHOD_HW_FRAMES_CTX, for example QSV in FFmpeg 4.x) or when FFmpeg creates it for a hardware accelerated decoder while decoding the first packet.

The method may return an invalid context before that point, and for decoders that keep the context only inside the decoded frames. VideoFrame::hwFramesContext() always returns the context of a produced frame.

Returns
the frames context owned by the decoder, or an invalid value when there is none yet

◆ setHwDeviceContext()

void av::VideoDecoderContext::setHwDeviceContext ( const hw::DeviceContext & device,
OptionalErrorCode ec = throws() )

Must be called after the codec is set and before open(). The decoder uses the device to choose the output pixel format; there is no silent software fallback. If the codec has no hardware configuration for the device type, open() fails with Errors::HardwareConfigNotFound.

The function installs an internal get_format() callback. It does not use AVCodecContext::opaque.
